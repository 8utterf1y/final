#### 跨函数取证:沿调用链补齐上下文

借助代码索引,AI 不只看眼前片段,还能顺着调用链"翻到"被调函数的定义再下结论。

只看孤立片段时，模型看不到被调函数的真实实现、 拿不到调用链上下文，结论常”想当然”。学界已反复证明 **仓库级上下文** 的价值：RepoCoder（EMNLP 2023）用迭代检索把散落 多文件的上下文喂给模型，较”仅看本文件”提升 **10%** ​**以上**​；AutoCodeRover（ISSTA 2024）进一步指出应使用 ​**程序结构（AST）+** **迭代代码搜索** 而非整文件/碎片检索来定位与取证。

* ​**贴段代码问大模型：缺乏仓库级上下文，易幻觉、易误判。**​:
    * 通常只盯着 `parse(buf)` 提一句"注意空指针",看不到 `fopen` 句柄泄漏，也无法判断 `read_all` 是否真会返回 `NULL`。
    * ​**本平台**​:索引到 `read_all` 定义后做跨函数取证,同时报出 ①`fp` 句柄泄漏、②`*out` 未校验导致
    `parse` 解引用风险,并给出 **文件:行号** 定位、**证据代码块** 与 ​**完整推理过程**​。


#### ​**大模型语义推理（L3）+ L4 多阶段链路**

单轮提问难以自我纠错；而 LLM 自身也会”幻觉出不存在的 bug”—— OpenAI 的 CriticGPT（2024）既证明 ​**批评式（critic​）模型能比人工抓到更多 bug**​，也指出 critic 自身会 hallucinate， **人机协同 +** **可核验证据** 才最稳。同时，结论若不能逐条回看推理与证据，就无法研判、复盘与跨团队协作。


* **一次性提问不可靠、不可审计，缺协作沉淀。**
    * 单轮容易”想当然”放过，多阶段靠 **质疑 +** **取证** 兜住， 且每一步都留痕、可回看（这也是能研判与协作的前提）。 


**痛点分析 → 方案设计决策**

| 痛点                            | 本方案的设计决策                                                                                                                                                 |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| ③ 缺仓库级上下文               | ​**索引驱动的跨函数上下文（cpp-ctx**​​**）**​：tree-sitter 建符号表/调用图，按需双向 BFS 取数                                                    |
| ①②④ 漏语义/弱泛化/单轮不可靠 | ​**大模型语义推理（L3**​**）+ L4** ​**多阶段链路 Actor→Critic→ReAct→Refiner**​：初判→自我质疑→调工具取证→定级收敛                    |
| ④ 不可审计 / AI 幻觉           | **证据策略 +** ​**全程留痕（runs.db**​​**）**​：强制可定位证据，逐条回看提示词/响应/工具观测                                               |
| ④ 缺协作沉淀 / 未融入流程      | ​**平台化**​：研判（triage）+ 导出归档 + 定时调度 + 实时日志，把审查嵌入研发流程                                                                         |
| 可靠性/成本                     | **确定性 L3/L4** ​**流水线（非放任式 agent**​**）+ token** **预算裁剪 +** **结果缓存 +** **​主备模型/​**​**排队** |

**适用场景**

· 模块级 / 整仓级的 ​**周期性代码体检**​（配合定时任务，闲时调度）；

· 关键模块、变更热点的 ​**深度评审**​（L4 复核）；

· 交付前的 ​**缺陷清单沉淀与跨部门评审**​（导出 xlsx 归档）；

· **叠加在既有静态分析 / CI** **门禁之上** 的增量审查：传统工具守已知规则下限，AI 补语义 / 逻辑 / 跨函数缺陷，二者并行互补；

· 作为 ​**代码理解基础设施**​：cpp-ctx 亦可通过 MCP 被 IDE / Agent / CI 复用。


**端到端数据流**

一次审查任务的完整链路：

1. ​**登记项目**​：注册被审查的 C/C++ 仓库，平台自动初始化（写入 .cpp_review.yaml、rules/ 等）。
2. **建立 /** ​**更新索引**​：cpp-ctx 对整仓建立 index.db（符号、引用、include、调用图）；SHA-256 增量，仅重建变更文件。
3. ​**按需取上下文**​：对每个审查目标（函数/文件/目录展开的函数），沿调用链双向 BFS 取数，并按 token 预算裁剪。
4. ​**多阶段推理**​：cpp-review 按 L3 或 L4 编排大模型；L4 进入 Actor→Critic→ReAct→Refiner 链路，跨函数取证。
5. ​**落库与聚合**​：推理链、证据、用量写入 runs.db；平台侧聚合为可过滤、可研判、可导出的结果库。
6. ​**研判与归档**​：用户逐条研判（确认/误报/忽略），按需导出 xlsx 归档。

**组件职责边界**

* **cpp-ctx** 只负责”代码理解与取数”，不调用 LLM，可独立使用（CLI / Python / MCP）。

* **cpp-review** 只负责”推理编排与结果生产”，把”给多少上下文”交给 cpp-ctx、把”调度与展示”交给平台。

cpp-ctx 是整条流水线的”眼睛”：把整仓 C/C++ 解析成 **符号表 +** **调用图 + include** **关系** 落入一份 SQLite 索引，再按需把任意函数的相关上下文打包给模型——让大模型”通读上下文后再判断”，而不是只看 孤立片段。它不是简单的 grep / 正则，而是一套 ​**可被复用的代码理解基础设施**​。

**索引构建**

· **tree-sitter** ​**解析，不依赖能否编译**​：容错强、跨平台；需要更精确时可结合 compile_commands.json 走 clang -E 预处理，精准还原宏与 include。

· **增量 +** ​**并行索引**​：SHA-256 指纹比对，改了哪个文件只重建哪个；线程池并行解析，百万行级大仓也能快速建库。

· **SQLite** **单文件索引** ​**index.db**​：符号 / 引用 / include / 调用关系全进库，​**只读查询、多读者并发不阻塞**​， 天然适合被多端（cpp-review、CI、MCP 客户端）共享。

**按需取上下文**

把”喂多少上下文”变成可控的工程参数，而不是一股脑全塞给模型：

​**双向按需取数**​：沿调用链向下（depth，目标调用了谁）、调用者向上（caller_depth，谁调用了目标）做 BFS，要多深给多深。

**MCP** ​**能力**​——cpp-ctx 内置一个 ​**MCP**​​**（Model Context Protocol**​​**）服务**​：以 line-delimited JSON-RPC 2.0 over **stdio** 暴露一组 **只读** 工具，任何兼容 MCP 的客户端都能直接接入、按需取数：

| MCP 工具                       | 作用                                                                                 |
| -------------------------------- | -------------------------------------------------------------------------------------- |
| get_function_context         | 取单函数上下文，支持 depth / caller_depth / max_tokens 裁剪，输出 Markdown 或 JSON |
| search_symbols                | 按 名称 / 类型 / 模块 / 通配 过滤符号                                                |
| find_callers · find_callees | 沿调用图向上 / 向下 BFS                                                              |
| list_modules · module_map   | 模块表与文件清单                                                                     |
| tools/list                     | 自描述：列出全部工具与参数                                                           |


**L3：单次推理**

L3 走 ​**单轮规则评审**​：把目标函数 + 上下文 + 规则一次性交给模型，快速产出问题清单。 速度快、token 省，适合 ​**全量扫描与日常回归**​。

**L4：多阶段深审（Actor → Critic → ReAct → Refiner）**

L4 进入多阶段链路，逐级自我质疑与跨函数取证：

1. ​**Actor（初判）**​：基于上下文与规则给出初步问题判断；
2. ​**Critic（质疑）**​：对初判逐条提出反问/质疑，挑出证据不足或可能误报之处， 并可发出 drop 信号让弱证据 finding 被后续直接删除；
3. ​**ReAct（取证）**​：按需调用工具（查定义 / 找调用者 / 读片段）沿调用链补齐证据；
4. ​**Refiner（收敛）**​：综合证据定级、去误报、合并重复，产出最终结论。
