📖 一、增量索引：SHA-256 指纹比对的完整实现
1.1 SHA-256 指纹计算（cache/hash.py）
_BUF_SIZE = 1 << 16  # 64 KB 分块
def sha256_of_file(path: Path) -> str:
    """Compute SHA-256 hex digest of `path` (streamed)."""
    h = hashlib.sha256()
    with path.open("rb") as f:      # 二进制模式，按原始字节哈希
        while True:
            chunk = f.read(_BUF_SIZE)   # 64KB 分块读取，不整读进内存
            if not chunk:
                break
            h.update(chunk)
    return h.hexdigest()
要点：
- 只哈希文件内容（不含路径），路径单独存 DB
- 64KB 流式读取，大文件不占内存
- 二进制模式 "rb"，不做文本编码转换

1.2 两阶段比对：worker 线程 + 主线程
阶段 A：worker 线程做 L1 缓存比对（_parse_one）
def _parse_one(sf, parse_mode, compile_args_by_path, l1, clang_bin) -> _ParseResult:
    """Worker：SHA + L1 查找 + parse。可在线程池中安全调用。"""
    path = Path(sf.abs_path)
    if not path.is_file():
        return _ParseResult(sf, sf.abs_path, "", None, False, "file not found")
    sha = sha256_of_file(path)                    # ① 计算文件 SHA-256
    cached = l1.get(sha, parse_mode)              # ② L1 缓存按 (sha, mode) 查
    if cached is not None:
        return _ParseResult(sf, abs_posix, sha, cached, True, None)  # ③ 命中→零解析
    pf = parse_file(path, lang=sf.lang, parse_mode=parse_mode, ...)  # ④ 未命中→解析
    l1.put(pf)                                    #    写入 L1
    return _ParseResult(sf, abs_posix, sha, pf, False, None)
> L1 命中意味着：同一个 SHA-256 的文件之前解析过 → 连 tree-sitter 解析都跳过，直接复用 pickle 的 ParsedFile。
阶段 B：主线程做 DB 指纹比对（_drain_one，核心 SKIP 条件）
existing = writer.get_file_fingerprint(abs_posix)   # (file_id, sha256, parse_mode)
if (
    existing is not None        # ① DB 中已有该文件行
    and existing[1] == sha      # ② SHA-256 一致
    and existing[2] == parse_mode  # ③ 解析模式一致
):
    # ===== 三个条件全满足 → SKIP =====
    writer.touch_file_parsed_at(existing[0])   # 只更新 parsed_at 时间戳
    writer.commit()
    stats.files_skipped_unchanged += 1          # 统计跳过
    return
# ===== 任一条件不满足 → 全量重建该文件 =====
fid = writer.upsert_file(...)                  # ① upsert 文件行
writer.replace_file_data(fid)                  # ② DELETE 旧 symbols/refs/includes
writer.insert_symbols(fid, ...)                # ③ 重新 INSERT
writer.insert_refs(fid, ...)
writer.insert_includes(fid, ...)
writer.commit()
SKIP 三条件（缺一不可）：
条件	作用
行存在	防止新文件误判为"未变"
SHA 一致	内容没变
parse_mode 一致	ts_only ↔ ts_accurate 切换会导致缓存失效（即使内容相同）

1.3 三个关键 SQLite 操作（sqlite_writer.py）
① get_file_fingerprint — 读取比对基准
def get_file_fingerprint(self, abs_path):
    row = self.conn.execute(
        "SELECT id, sha256, parse_mode FROM files WHERE abs_path = ?",
        (abs_path,),
    ).fetchone()
    return (int(row[0]), str(row[1]), str(row[2])) if row else None
② touch_file_parsed_at — 未变文件只刷时间戳
def touch_file_parsed_at(self, file_id):
    now_epoch = int(time.time())
    self.conn.execute(
        "UPDATE files SET parsed_at = ? WHERE id = ?", (now_epoch, file_id)
    )
    # sha256、parse_mode 及其它列全部不动
③ replace_file_data — 变化文件清空子数据
def replace_file_data(self, file_id):
    self.conn.execute("DELETE FROM symbols WHERE file_id = ?", (file_id,))
    self.conn.execute("DELETE FROM refs WHERE file_id = ?", (file_id,))
    self.conn.execute("DELETE FROM includes WHERE src_file_id = ?", (file_id,))
    self.conn.execute("DELETE FROM parse_errors WHERE file_id = ?", (file_id,))

1.5 失效文件清理（prune_stale_files）
def prune_stale_files(writer, *, kept_file_ids, module_ids=None):
    targets = module_ids if module_ids is not None else writer.list_all_module_ids()
    pruned = 0
    for mid in targets:
        for fid in writer.list_file_ids_for_module(mid):
            if fid not in kept_file_ids:   # 本次未被索引到 → 文件已被删除
                writer.delete_file(fid)    # 级联删除
                pruned += 1
    writer.commit()
    return pruned
def delete_file(self, file_id):
    self.replace_file_data(file_id)                    # 先删 4 张子表
    self.conn.execute("DELETE FROM files WHERE id = ?", (file_id,))  # 再删文件行
注意：文件被删除时，它在文件系统上消失 → _parse_one 返回 "file not found" 错误 → 该文件 id 不在 kept_file_ids → 走 prune 路径级联删除。

1.6 并行架构（线程安全设计）
with ThreadPoolExecutor(max_workers=workers) as pool:
    futures = [pool.submit(_parse_one, sf, ...) for sf in sources]
    for fut in as_completed(futures):
        _drain_one(fut.result())   # ← 所有 SQLite 写都在主线程
操作	执行线程	原因
SHA 计算	worker	纯 CPU/IO，可并行
L1 缓存查/写	worker	pickle 文件操作，原子写安全
get_file_fingerprint 比对	主线程	避免多线程并发 SQLite
touch/replace/insert	主线程	SQLite 写串行化
as_completed 收尾	主线程	结果乱序到达，逐个处理

1.7 三种场景全流程
场景	100 文件首建	改 1 个文件
L1	100 MISS → 全解析	99 HIT + 1 MISS
DB 比对	100 无行 → 全 INSERT	99 SHA 匹配 → 只 touch + 1 SHA 变 → 重建
重建范围	100 文件	仅 1 个文件（99 个只更新时间戳）
Prune	无	无
耗时	首次全量	增量秒级
> 核心收益：10 万行仓库，改 1 个文件后重索引 = 只解析那 1 个文件 + 99 个时间戳更新，从"5 分钟"降到"秒级"。
